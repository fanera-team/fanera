# Дизайн Fanera

Рабочий документ для [#21 — токены и стиль](https://github.com/fanera-team/fanera/issues/21) и [#22 — лоу-фай макеты](https://github.com/fanera-team/fanera/issues/22). Требования к продукту и правам пользователей описаны в [system-design](../system-design/onboarding.md).

## Источник макетов

Рабочий макет — облачный файл [Fanera Design в Penpot](https://design.penpot.app/?screen=viewer&file-id=51f2d744-23b9-8138-8008-f43d2bb86a56&page-id=ab9b75aa-429a-802c-8008-f460534539f2&section=interactions&frame-id=ab9b75aa-429a-802c-8008-f4661b667f20&index=0&share-id=34bf9ccd-91f6-4266-984e-3a44b85691b8). Для редактирования нужен доступ к файлу в команде Penpot. Изменения в файле сохраняются автоматически. В задачах указывайте страницу, макет и состояние; при необходимости прикладывайте прямую ссылку на нужный макет.

Макет задаёт внешний вид и композицию, `docs/system-design` — поведение, данные и права. Источник макетов и способ передачи в разработку записаны в [Р-66](../system-design/decisions.md#макеты-и-передача-в-разработку); выбор темы и шрифта — в Р-67 там же.

### Работа с макетом через MCP

1. Войдите в Penpot через почту, которую вы указали в чате Telegram для Google Календаря. На неё отправлено приглашение в проект с макетом. Примите приглашение и убедитесь, что файл Fanera открывается в вашем аккаунте.
2. В Penpot откройте **Your account → Integrations → MCP Server**, включите сервер, создайте личный MCP-ключ и скопируйте предложенный адрес сервера. Адрес содержит ключ в параметре `userToken`; не публикуйте его в репозитории, задачах, чатах и снимках экрана. [Инструкция Penpot](https://help.penpot.app/mcp/).
3. Добавьте сервер **через UI своего агента**:
   - **Codex:** **Settings → MCP servers → Add server**. Название — `penpot`, тип — **Streamable HTTP**, адрес — скопированный из Penpot. Сохраните настройку и нажмите **Restart**. [Инструкция Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
   - **Claude (личный аккаунт, web или Desktop):** откройте **Customize → Connectors → + Add → Add custom connector**. Назовите подключение `Penpot`, вставьте свой адрес из Penpot как URL удалённого MCP-сервера и при выборе способа авторизации укажите **No sign in**: ключ уже включён в URL. Завершите добавление и включите коннектор в нужном чате через **+ → Connectors**. В **Claude Team/Enterprise** коннекторы добавляет администратор для всей организации; не передавайте ему свой URL с личным `userToken`, иначе участники будут работать через общий ключ. [Инструкция Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).
4. Откройте файл в Penpot и выберите **File → MCP Server → Connect**. Во время работы держите вкладку открытой: MCP работает с текущей страницей активной вкладки. [Инструкция Penpot](https://help.penpot.app/mcp/).
5. Проверьте подключение запросом к агенту: «Через Penpot MCP перечисли страницы открытого файла, ничего не изменяя». Для следующих задач указывайте страницу, конкретный макет и состояние.

## Принятые решения об интерфейсе

- После входа пользователь видит доступные рабочие пространства. Выбор пространства открывает список его досок. Для обоих списков показаны пустое состояние, загрузка и ошибка.
- В левом верхнем углу навбара находится кнопка открытия сайдбара. «Создать пространство» — компактная кнопка с иконкой из общего набора.
- При открытом сайдбаре бургер в Navbar скрыт. Меню пользователя открывается по нажатию на аватар и выравнивается по его правому краю; закрывается повторным нажатием, `Esc` и нажатием вне меню, после чего фокус возвращается на аватар. Меню содержит данные аккаунта, профиль, настройки, переключатели темы и языка, выход. Подписи пунктов в макете предварительные: перед реализацией нужны согласованные переводы `ru`/`en`.
- На доске холст занимает основную область, инструменты находятся сверху, настройки выбранного инструмента — слева, свойства выделенного объекта — справа.
- Цвет стикера выбирают слева до размещения. После клика по холсту можно сразу вводить текст; инструмент остаётся активным до `Esc` или выбора другого.
- Текст по умолчанию выравнивается слева. В кнопке без иконки надпись центрируется; в кнопке с иконкой содержимое идёт слева после значка. Содержимое кнопок центрируется по вертикали. Текст внутри фигур и стикеров центрируется по обеим осям.
- Статус сохранения выглядит как небольшой округлый бейдж с цветной подложкой, точкой и подписью. Он визуально отличается от кнопки. Для состояний предусмотрены сохранение, процесс сохранения, потеря связи и ошибка сохранения.
- Контур фигур — 2 px; у ромба скруглены углы. Цвет текста стикера остаётся тёмным в обеих темах, чтобы надпись читалась на светлой бумаге.
- В UI-kit есть три вида подсказки (`Tip`): информация, предупреждение, ошибка — для обеих тем. У стикера, панели и плавающей панели показаны разные уровни тени.

Это решения для макета. Интерактивный прототип каждого действия в рамках #22 не требуется.

## Цвет и типографика

Единственная актуальная палитра — **«Холодный графит»** в светлой и тёмной темах. Дальнейшие изменения развиваем на её основе. Цвета управления отделены от цветов объектов на доске. Для всех экранов и компонентов используется **Montserrat**.

### Иконки Lucide в коде

`lucide-react` уже установлен в `apps/web`. Общий [`Icon`](../../apps/web/src/shared/components/ui/icon/icon.tsx) принимает типизированный строковый ключ, например `<Icon name="menu" />`, и задаёт размеры 16/20/24 px и толщину линии 2 px. Статические именованные импорты собраны в отдельном [`iconMap`](../../apps/web/src/shared/components/ui/icon/icon-map.ts); он же даёт список ключей для [галереи Storybook](../../apps/web/src/shared/components/ui/icon/icon.stories.tsx). Неизвестное имя — ошибка TypeScript. Отдельная библиотека копий SVG не нужна.

Реестр включает основные и часто используемые иконки. Каждый ключ в нём добавляет соответствующий модуль в приложение, даже если конкретный экран его не показывает; при росте списка измеряем бандл и убираем лишнее. Отдельная предзагрузка иконок не нужна: она увеличит начальную загрузку. Для имён, приходящих из внешних данных, можно отдельно рассмотреть `DynamicIcon`; [Lucide предупреждает](https://lucide.dev/guide/react/advanced/dynamic-icon-component) о дополнительных модулях, запросах и задержке появления иконок при таком подходе.

Для действия используйте общую `Button` с иконкой; у кнопки без текста должно быть доступное имя, а декоративный SVG остаётся скрытым от скринридера. Не дублируйте геометрию Lucide в JSX или отдельных SVG. Названия иконок, применённых в макете, записывайте в [карте компонентов](component-map.md). Официальное описание пакета: [Lucide React](https://lucide.dev/guide/react/).

Названия токенов отражают их назначение: например, основная кнопка использует `primary` и `primary-foreground`. Библиотеку иконок и примеры размеров смотрите на странице `Иконки`; образцы теней — на страницах UI-kit. Точные параметры теней перед вёрсткой сверяются с выбранными слоями Penpot.

## Как передавать макет в вёрстку

1. Указать разработчику страницу Penpot, конкретный макет и состояние, а также соответствующие требования из `docs/system-design`. Для просмотра использовать [общую ссылку](#источник-макетов); для редактирования — доступ команды.
2. Через Penpot MCP или режим Inspect проверить свойства нужных слоёв. При необходимости экспортировать утверждённые экраны в `docs/design/exports/` и передать пути вместе с именем экрана. Иконки сверять со страницей `Иконки` и реализовывать через уже установленную библиотеку Lucide.
3. Реализовать интерфейс в структуре `apps/web`, собирая повторяемые элементы из `apps/web/src/shared/components/ui`, и сравнить результат с макетом в обеих темах. Смысловые токены есть в [CSS-теме](../../apps/web/src/shared/styles/globals.css); перед вёрсткой сверить их значения с актуальными токенами Penpot. Макет описывает внешний вид, а поведение и права — `docs/system-design`.

Общая ссылка предназначена для просмотра. Доступ к редактированию и настройкам файла определяют роли команды Penpot. Не публикуйте в задачах и документации MCP-адреса с токенами доступа.

## Состояние работы

1. Карта экранов и лоу-фай макеты #22 готовы: лендинг, вход, регистрация, рабочие пространства, доски и экран доски. Все основные экраны представлены в светлой и тёмной темах; для списков пространств и досок показаны пустое состояние, загрузка и ошибка.
2. «Холодный графит» и Montserrat закреплены в Penpot и CSS-теме. UI-kit содержит образцы для обеих тем, набор иконок — базовые размеры. Значения 103 токенов наборов `FaneraLight`, `FaneraDark` и `FaneraShared` сверены с CSS-темой; три токена `FaneraPilot` дублируют уже учтённые значения.
3. Перед вёрсткой остаётся согласовать содержимое отдельных сценариев, проверить состояния доступа и подготовить экспорты конкретных экранов.

### Открытые вопросы

- Уточнить тексты и степень выразительности лендинга относительно рабочих экранов.
- По мере проработки сценариев дополнить UI-kit участниками, масштабом, панелью «Поделиться» и состояниями ограниченных прав.
- В [Р-65](../system-design/decisions.md) лендинг описан как часть SPA, а в [backlog T9-02](../system-design/backlog.md) назван SSG. Перед реализацией нужно согласовать формулировку; на композицию макета это не влияет.

## Состояние кода

В `apps/web` уже есть Tailwind CSS, shadcn/ui и `lucide-react`. [CSS-тема](../../apps/web/src/shared/styles/globals.css) содержит смысловые цвета двух тем, постоянные цвета объектов доски, типографику, отступы, скругления и размеры иконок. Класс `.dark` задаёт тёмные значения. [Переключатель темы](../../apps/web/src/shared/components/ui/theme-toggle/theme-toggle.tsx) сохраняет выбор в `localStorage`; скрипт в `index.html` восстанавливает его до первого отображения. В Storybook темы переключаются глобально для всех stories. Montserrat загружается через Google Fonts в CSS, поэтому для его загрузки при первом открытии нужна сеть. Дополнительных npm-зависимостей для #21–23 не добавляли. Текущая страница приложения остаётся демонстрационным каркасом; компоненты приводятся к макету отдельно.

При изменении палитры сначала обновите токены в Penpot, затем синхронизируйте значения в CSS и проверьте оба режима. Сопоставление: `light.*` → `:root`, `dark.*` → `.dark`, `shared.*` → общие значения в `:root`; camelCase в Penpot становится kebab-case в CSS, например `light.primaryForeground` → `--primary-foreground`. `shared.fontSans` соответствует `--font-sans` в `@theme inline`. `radius-*-token` отделяют исходные размеры от переменных Tailwind `--radius-*`. `popover`, `secondary` и `sidebar` используют близкие смысловые цвета для совместимости с текущими компонентами shadcn/ui.
