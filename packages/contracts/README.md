# @fanera/contracts

Общие Zod-схемы и типы REST-контрактов для фронтенда и бэкенда.

Публичный API находится в `src/index.ts`. Импортируем только через
`@fanera/contracts`, не из внутренних файлов пакета. Типы не дублируют схемы:
они получаются через `z.infer`, поэтому контракт меняем только в схеме.

В пакете нет NestJS, React и доступа к окружению. `envSchema` остаётся на сервере,
как и фильтр ошибок с пайпом валидации.

## Разработка

`pnpm install` собирает пакет через `prepare`. Экспортируются JavaScript ESM
и декларации типов из `dist`, поэтому пакет работает в Node без загрузчика TypeScript.
`dist` не коммитим.

- `pnpm --filter @fanera/contracts build` — пересобрать после изменений.
- `pnpm --filter @fanera/contracts dev` — наблюдать за изменениями.
- `pnpm --filter @fanera/contracts typecheck` — проверить типы.

Корневые `dev`-команды следят за контрактами, но после их пересборки сервер нужно
перезапустить: Nest не следит за `node_modules`. Перед локальным `pnpm test` соберите
пакет; в CI и корневом `pnpm build` зависимости собираются автоматически.

Изменения общего контракта затрагивают и фронт, и бэк: сначала согласуем их в
[OpenAPI](../../docs/system-design/api/rest_api.yml) по Р-47.
