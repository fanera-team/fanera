# @fanera/contracts

Общие Zod-схемы и типы REST-контрактов для фронтенда и бэкенда. Источник контракта —
сами схемы: типы выводятся через `z.infer`, поэтому меняем контракт только в схеме.

Единственный публичный API — [src/index.ts](src/index.ts). Приложения импортируют
схемы и типы через `@fanera/contracts`, не из внутренних файлов или подпутей пакета,
и не дублируют контрактные типы.

## Структура

В `src` используется плоская структура: один файл на предметную область или общую
часть контракта. Схемы, метаданные OpenAPI и выведенные через `z.infer` типы лежат
вместе. Файлы областей переэкспортируются через `export *` в `index.ts`.

Для запросов и ответов используются суффиксы `*Request` / `*Response`, для сущностей —
существительные. В существующих REST-схемах входных данных также используется суффикс `*Body`.

Пакет не зависит от React или NestJS и не обращается к окружению.
Внутренняя валидация и обработчики приложений остаются в самих приложениях.

Целевой API описан в [rest_api.yml](../../docs/system-design/api/rest_api.yml),
текущий контракт этапа публикуется в Swagger сервера.

Сервер и фронтенд подключают пакет через `workspace:*`.

## Разработка

`pnpm install` собирает пакет через `prepare`; в `dist` лежат ESM и декларации типов,
`dist` не коммитим.

- `pnpm --filter @fanera/contracts build` — пересобрать.
- `pnpm --filter @fanera/contracts dev` — наблюдать за изменениями.
- `pnpm --filter @fanera/contracts typecheck` — проверить типы.

Корневые `pnpm dev`, `pnpm dev:web` и `pnpm dev:server` включают наблюдение за
контрактами. После пересборки `dist` сервер нужно перезапустить: `nest start --watch`
не следит за `node_modules`.

**Правило:** любая одноразовая команда приложения, которая читает `@fanera/contracts`
(`build`, `typecheck`, `test`, `test:e2e`), сначала собирает пакет. Поэтому в скриптах
приложений стоит `pnpm --filter @fanera/contracts build && ...`. В dev-режиме сборку
делает watcher. Тесты и приложения читают собранный `dist`
(в CI это дополнительно делает `prepare` при установке). Корневой `pnpm build`
собирает зависимости перед приложениями.

Изменения общего контракта затрагивают и фронт, и бэк: сначала согласуем OpenAPI по Р-47.
